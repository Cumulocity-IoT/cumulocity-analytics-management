Adding an extension

Choose a repository in the list at the top of this page to browse its blocks. Select Add extension to start the wizard. It offers three paths:

  • Deploy a release: pick a release asset of a repository. The backend service downloads and deploys it. Without the backend service, you download the file and upload it in the next step.
  • Build a new extension: choose the blocks of one repository, name the extension and create it.
  • Upload a file: upload an extension *.zip from your computer.
Start from selected blocks

Tick rows in the list first, then select Add extension. The wizard starts at the name step with these rows chosen. Rows that are already installed, are not monitor files, or conflict with a chosen row cannot be selected, and the wizard shows the reason.

After creating

The wizard offers an optional restart of the Streaming Analytics engine so the new blocks load. The version of an uploaded or released extension is stored in its metadata, not in its name.

Repository layouts

Two layouts of GitHub repositories are supported to build an extension.

Layout 1: directory is extension

How it works

  • The builder inspects the top-level items in the configured repository path.
  • A .mon file (e.g. Difference.mon) becomes a single-file extension.
  • A directory (e.g. Python) becomes an extension that packages all of its content, including subdirectories like venv. Directories need the backend service.

What you see

  • A list of the top-level .mon files and directories (e.g. "Difference", "Offset", "Python"). You can select several; they are built together into a single extension.
Layout 2: configuration file extensions.yaml

A configuration file defines the contents of the extensions explicitly.

How it works

  • The builder looks for extensions.yaml among the same top-level items as in layout 1. It is not found in a subdirectory.
  • The file holds named sections, each listing the files to include. A section's files are not limited to *.mon.
  • Without the file, the repository is treated as layout 1.

What you see

  • Only the section names, not the files inside them. You can select several sections. Sections need the backend service and cannot be combined with individual files in one extension.
