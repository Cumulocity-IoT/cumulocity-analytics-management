Two layouts of GitHub repositories are supported to build an extension:

1. Directory is Extension

Mechanism

  • The extension builder inspects the top-level items in the configured repository path.
  • If an item is a .mon file (e.g. Difference.mon), a single-file extension is created from just that file.
  • If an item is a directory (e.g. Python), an extension is created by packaging all the content within that directory (including subdirectories like venv).

User UI

  • The user sees a list of names for each top-level .mon file and top-level directory (e.g. "Difference", "Offset", "Python"). The grid allows selecting several of these at once, but only a single file or directory may be submitted per build — selecting more than one is rejected when the build is started.
2. Configuration File extensions.yaml

This layout uses a dedicated configuration file to define the extension's contents explicitly.

Mechanism

  • The builder looks for a configuration file named extensions.yaml among the same top-level items as layout 1 (it is not found if placed in a subdirectory).
  • If the file exists, the builder reads it for the extension's metadata: a set of named sections, each listing the files to include. Multiple sections can be selected and built in one request, and a section's files are not limited to *.mon.
  • If no config file is present, it defaults to listing simple .mon files/directories as in layout 1.

User UI

  • If the config file is present, the UI only shows the top-level section names defined in the file, not the embedded files or directories.
