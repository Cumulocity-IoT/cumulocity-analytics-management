## Open findings (not changed, need a decision)

1. **ADR-002 is not enabled (documented as such).** `ErrorInterceptor`/`HttpModule` are never imported; `ErrorHandlerService` is unused. Enabling it would also retry non-idempotent POSTs (`/extension/*`) up to 3x. Restrict retries to GET/idempotent methods before wiring it.
2. **ADR-004/005 are not (fully) implemented (documented as planned/partial).** No Pydantic, rate limiting, response envelope (`success/data`), `/extension` GET/POST or `/repository` routes. `/health` returns `{"status": "UP"}`; `health_check.py` is dead code (0% coverage).
3. **Rebuild is destructive:** the old extension is deleted *before* download/build; a build failure leaves no extension.
4. `delete_extension_by_id` maps every `C8YAgentError` (including auth failures) to 404; delete-by-name maps to 500.
5. `_download_github_content` catches `ValueError` around the recursive listing loop, so a path-traversal `ValueError` from `_safe_join` is swallowed and the URL is written as a single file.
6. YAML section `files` entries are joined into the repository URL unchecked (`../`).
7. `requirements.txt` is unpinned; `AGENT.md` and other root docs were not reviewed for drift.
8. (done) `test-http.service.ts` debug code removed. `EngineMonitoringComponent` still calls `EventService` directly.
9. `ExtensionInventoryService.uploadExtension` in update mode deletes the old binary *before* uploading (same destructive pattern as backend rebuild).
10. Karma is deprecated upstream; consider migrating to Vitest (`ng test`) later.
